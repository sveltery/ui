## Principal conclusions

- Modern `cn` is a standalone, framework-independent package with its own class-merging engine. The selected UI app pin is **0.2.2**, now genuinely landed; the same upstream CLI/registry importers separately select **0.2.4**. Mixing these pins would not be fidelity to the audited UI app. `tailwind-merge` is only a development conformance oracle in current UI, not the product merge engine.
- `shadcn` **4.21.1** is more than a CLI. It exports framework-independent Tailwind CSS, browser-safe presets, icon metadata/templates, schema/registry/utils and Node CLI/MCP tooling. Upstream globals import `shadcn/tailwind.css`; current UI does not declare/import it. This is a concrete omitted delivery/configuration dependency; no current runtime animation failure is inferred.
- It is unsafe to assume the entire Base API is already interchangeable. Upstream UI selects **@base-ui/react 1.6.0**. Current UI consumes Sveltery Base **d889e75**, archive **cc6bcbdf…**, derived from React Base **1.8.0**, and exposes only ten bounded public subpaths. A pending f884 pin would add two modules but is not yet consumed. Headless internals remain separately managed.
- Source fidelity requires more than styled wrappers: native **MessageScroller and Questionnaire** come from `@shadcn/react 0.3.1`; their React hooks/primitives need a Svelte implementation. Pure geometry/stores/collections/helpers can be retained. They remain unimplemented here.
- Do not copy an older generic shadcn dependency list: the current **Base Drawer imports @base-ui/react/drawer, not vaul**; the 62-wrapper registry has **no form.tsx**; native Textarea does **not** import react-textarea-autosize. React Hook Form, Formisch, TanStack Form, DnD and table engines are optional form/app/block scope, not unconditional runtime requirements.

## Docs, configuration, CLI and build tooling

Nothing in this audit authorizes installing every app/CLI dependency in the UI runtime.
