## Landed fidelity repairs

The [merged Dialog forwarding/ref repair PR #10](https://github.com/sveltery/ui/pull/10) restores the pinned shadcn wrapper's absent-children forwarding for Trigger, Close, Title, Description and Overlay. The source is [Dialog at `d75a96ab781f3d659be1ad287347d5887ce9f2fc`](https://github.com/shadcn-ui/ui/blob/d75a96ab781f3d659be1ad287347d5887ce9f2fc/apps/v4/registry/bases/base/ui/dialog.tsx), with behavior compared against the unchanged [Base `4dd04e495fc9f5bb6a0bb872fe103563d49535b1` Element](https://github.com/sveltery/base/blob/4dd04e495fc9f5bb6a0bb872fe103563d49535b1/packages/base/src/lib/dialog/Element.svelte). React passes omitted children through; Base receives an absent snippet. UI previously supplied an empty implicit snippet and suppressed render fallback labels. Direct snippet forwarding restores absence while retaining explicitly supplied and explicitly empty snippets. The [paired DOM cases](../tests/dom/dialog-forwarding.test.ts) and [SSR/hydration browser cases](../tests/browser/dialog-forwarding.spec.ts) preserve that distinction. Content's composed children and built-in closes remain intact. This is a fidelity repair, not an intentional behavioral divergence; the maintainer approved implementing it on 2026-10-02. Landed as `6908902a76b433094fca57364a54b19428cb8c8e`; reviewed head `8b54b94056197904abf920d5494e3d2878f51fcd` passed [CI](https://github.com/sveltery/ui/actions/runs/36953258435), [Documentation](https://github.com/sveltery/ui/actions/runs/36953258448), independent review and [automatic review](https://github.com/sveltery/ui/pull/10#issuecomment-5944389730).
