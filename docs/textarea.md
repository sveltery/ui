# Experimental native Textarea

## Landed direct remote-field interoperability gates

The isolated [remote-field fixture](../apps/docs/remote-fields-fixture/src/routes/+page.svelte) spreads the actual pinned Kit `fields.text.as('text', 'Draft')` attributes directly onto public `Textarea`, without filtering props or supplying a field adapter. It uses Svelte 5.57.1, Kit 2.70.3 and the archive selected by the checkout's Base lock. The remote-field test scope itself preserved the original archive; the [separate landed Base pin update](upstream-differences.md#landed-base-pin-and-native-ref-adaptation) changes that archive without changing native Textarea props, implementation or accepted reset behavior. Experimental remote-function/async compiler opt-ins are confined to this test app and generated test consumers; the production docs configuration and framework-agnostic Base/UI packages are unchanged. No Bits, validator-library or other dependency is added.

The [typed contract](../apps/docs/remote-fields-fixture/src/routes/type-contract.ts), [validated fixture schema](../apps/docs/remote-fields-fixture/src/routes/schema.ts), [actual HTTP/SSR gate](../scripts/check-remote-fields.mjs), [main browser cases](../tests/browser/remote-fields.spec.ts) and [archive/source-copy browser cases](../tests/installation/remote-fields.spec.ts) cover direct spread, defaults/no-default values, setters, trusted edits, validation issues, enhancement/reset modes, no-JavaScript posts, pre-hydration edits and ref/attachment cleanup. Kit 2.70.3 mutates the cached form instance when `.enhance()` installs a callback; returning that instance does not restore its original callback. Default enhancement is therefore exercised on a fresh page, alongside a retain-to-reset transition and fresh-navigation regression. The custom reset fixture waits for Svelte `tick()` and calls the native form prototype so a reset control's ID cannot shadow the method; parsed submission results are still asserted. Kit's model is initially untouched by edits made before attachment: the UI textarea's SSR node and edited DOM value survive hydration, then real FormData submission carries the edit without a setter or synthetic replay. The native spread-only control also reuses its node, but this pinned compiler resets its pre-hydration edit to `Draft`; submission asserts that actual native value alongside UI's preserved edit. This field-model/hydration boundary is recorded separately from the native spread-only SSR baseline and earns no React parity credit. Fresh consumers validate the unchanged documented configuration before adding experimental test flags in a separate phase. The existing accepted native reset difference remains in the [compatibility register](upstream-differences.md); these SvelteKit checks earn no new React parity credit and introduce no component behavior change.

On this pin, a spread-only native textarea serializes `value`/`defaultvalue` attributes with empty SSR text content. That is an explicitly separate native baseline diagnostic, not positive Textarea SSR interoperability evidence. UI's existing SSR/defaultValue/newline compensation remains necessary and unchanged. Current Kit 3 documentation includes APIs absent from installed 2.70.3; tests use the installed contract. Local type/build/HTTP results do not establish secured browser behavior: [PR #12](https://github.com/sveltery/ui/pull/12) landed as main `dcabf10d1e85681fcb29cf9f39e983a5a539ba28` after exact-head hosted results and independent/configured automatic reviews passed, recorded in the [compatibility evidence](upstream-differences.md#landed-direct-remote-field-test-scope). Later changes, including the separate Base pin candidate, need their own final-head gates.

Import `Textarea` from `@sveltery/ui` or `@sveltery/ui/textarea`. The single [registry component](../apps/docs/registry/bases/base/ui/textarea/Textarea.svelte) is packaged without a second implementation. It keeps the exact pinned class string, `cn` class conflict merging, caller-overridable `data-slot="textarea"`, and the [Nova section](../tests/reference/textarea-nova.css) from upstream lines 1336–1339. Native props include `name`, `form`, `rows`, `cols`, `wrap`, `required`, `disabled`, `readonly`, `minlength`, `maxlength`, accessibility attributes and native event handlers. It adds no variants, custom host, Base state or render API. A consumer supplies labels, descriptions and any explicit ARIA associations.

```svelte
<script lang="ts">
  import { Textarea } from '@sveltery/ui/textarea';
  let message = $state('');
  let node = $state<HTMLTextAreaElement | null>(null);
</script>
<label for="message">Message</label>
<Textarea id="message" name="message" bind:value={message} bind:ref={node} aria-describedby="message-help" required />
<p id="message-help">Write a message.</p>
```

`className` becomes Svelte `class` (including native class arrays/objects); React style objects become CSS strings. React refs become `bind:ref` and forwarded Svelte symbol attachments, with cleanup on removal. React synthetic `onChange` fires during editing; Svelte `oninput` observes editing and native `onchange` observes the committed edit on blur. These are accepted framework API substitutions; they do not establish acceptance of controlled-value or reset behavior.

`bind:value` updates the caller's Svelte state and native form reset restores `defaultValue` (or empty when absent) and updates bound state; React controlled `value` retains current state on reset. The [paired reset probe](../tests/browser/textarea.spec.ts) edits both fields to `Typed\nSecond`: reset leaves React at that value but resets Svelte to empty; both uncontrolled drafts reset to `Draft`. This intentional form-reset difference is accepted: retain native Svelte `bind:value` reset behavior, per the [recorded reset decision](https://github.com/sveltery/ui/pull/8). The decision covers reset, not ordinary form submission or broader React controlled-value semantics, and is separate from the accepted framework substitutions. Use `defaultValue` for an uncontrolled initial value/reset baseline. Framework-specific event/ref/binding and divergent reset assertions earn no React parity credit. Text content is supplied through `value`/`defaultValue`; React's deprecated textarea children initialization is outside this bounded slice.

The five [examples](../apps/docs/examples/base/TextareaExample.svelte) preserve the pinned placeholder, IDs, `rows=6`, invalid and disabled attributes, and description text. Native sections, headings, labels and a paragraph substitute for out-of-scope Example/Field components. The described example deliberately adds no `aria-describedby`: the pinned example supplies none explicitly, and full Field behavior/styling is not ported. The separate form fixture tests an explicit description association. The instruction “press enter to send” is retained source text; Textarea itself preserves native newline entry and implements no submit-on-Enter handler. This does not establish a shared upstream bug; a behavioral fix would require paired evidence and a deferred own-repository issue.

Nova is Tailwind input CSS. Use the [installation scaffold](installation.md)'s theme mappings and scan the current package output. Build archives and source copies from the same exact reviewed checkout selected in that guide. Textarea itself requires no Base primitive or upgrade; the checkout's separate Base pin update serves Dialog/Button. Native disabled styles, invalid/focus rings, field-sizing content, minimum height, overrides and responsive `text-base`/`md:text-sm` remain source rules; a dark palette is not supplied or validated.

## Evidence and remaining gates

[Source hashes](../tests/reference/textarea-sources.json) identify the byte-exact wrapper, complete five-state example and scoped Nova CSS. The actual pinned wrapper executes in [DOM comparisons](../tests/dom/textarea.test.ts) and [paired browser probes](../tests/browser/textarea.spec.ts). No dedicated upstream Textarea test file was identified; these are source-derived/local comparison tests, not copied upstream test ports. The MIT [reference license](../tests/reference/LICENSE) and package notices cover the derived fixtures.

Test-first commit `0048bb0` failed the missing Nova section assertion and failed DOM suite resolution because the component did not exist. A further [actual-wrapper SSR comparison](../scripts/check-textarea-ssr.mjs) failed when spread defaultValue produced an empty server textarea and when HTML parsing stripped a leading newline. The wrapper now uses the defaultValue fallback only during SSR and forwards defaultValue explicitly on the native host, and compensates for the parser newline only when serializing the binding. These restore pinned behavior rather than introduce intentional differences. Independent review of `579a1e37b4cf79115fefb9f0c61a9ba94552ce5e` found initially undefined bound values crashed on a lazy bindable fallback; regressions also reproduced an undefined ref crash before correction. Both bindings now have no component fallback, so native defaultValue/binding initialization adopts a supplied draft without rejecting undefined caller state. These are local fidelity repairs restoring valid native initialization, not changes to pinned upstream behavior. Fresh consumers and hydration also probe these bindings. Hosted [run 36937969780](https://github.com/sveltery/ui/actions/runs/36937969780) passed 44/45 browser cases; the remaining desktop growth comparison measured a focus-color transition at unequal times. The new comparison waits for the existing transition to settle without changing any pinned style or expected result. The next hosted [run 36938696726](https://github.com/sveltery/ui/actions/runs/36938696726) passed all 45 main browser cases but exposed missing input/change handlers in the new fresh-consumer fixture; its assertions correctly observed zero callbacks. The fixture now supplies those consumer handlers, preserving the existing expectations and component behavior. The implemented DOM tests compare default/overridden classes, data-slot and native attributes to the actual pinned React wrapper, then exercise Svelte binding, input/change, FormData, ref identity, symbol attachments, defaultValue reset and cleanup. Browser probes cover light Nova computed styles at 1280/390px, focus/invalid/disabled/override and content growth, paired labels/forms/validation/newlines, plus Svelte SSR/hydration and pre-hydration edits. The [package check](../scripts/check-package.sh) checks root/subpath identity, declarations, SSR initial/default values and styles. [Fresh consumer checks](../scripts/check-installation.mjs) add Textarea to archive/source-copy SvelteKit consumers alongside unchanged Button and Dialog.

Run `bash scripts/bootstrap.sh`, `bash scripts/verify.sh`, `bash scripts/check-installation.sh`, `pnpm test:browser` and `bash scripts/check-installation.sh --browser`. Later changes require hosted secured Chromium with retries zero, independent GPT-6.1 Sol high review and completed configured automatic review on their final head. [Merged PR #7](https://github.com/sveltery/ui/pull/7) records the completed implementation checks and reviews; earlier checks do not certify a later commit. Maintainers decide broader readiness. Full Field/Example APIs and visuals, React children/controlled semantics, dark palettes, Firefox/WebKit, IME/mobile device behavior and live assistive technology remain unclaimed.
