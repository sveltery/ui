# Experimental native Textarea

A bounded registry-owned Svelte 5 native textarea adapted from [shadcn's wrapper](https://github.com/shadcn-ui/ui/blob/d75a96ab781f3d659be1ad287347d5887ce9f2fc/apps/v4/registry/bases/base/ui/textarea.tsx) at `d75a96ab781f3d659be1ad287347d5887ce9f2fc`. It requires no Base Textarea primitive and preserves [the current Base lock](../scripts/base.lock.json). The package remains private and unpublished. These checks establish selected source contracts, not full shadcn API parity or production readiness.

Import `Textarea` from `@sveltery/ui` or `@sveltery/ui/textarea`. The single [registry component](../apps/docs/registry/bases/base/ui/textarea/Textarea.svelte) is packaged without a second implementation. It keeps the exact pinned class string, `cn` class conflict merging, caller-overridable `data-slot="textarea"`, and the [Nova section](../tests/reference/textarea-nova.css) from upstream lines 1336–1339. Native props include `name`, `form`, `rows`, `cols`, `wrap`, `required`, `disabled`, `readonly`, `minlength`, `maxlength`, accessibility attributes and native event handlers. It adds no variants, custom host, Base state or render API. A consumer supplies labels, descriptions and any explicit ARIA associations.

```svelte
<script lang="ts">
  import { Textarea } from '@sveltery/ui/textarea';
  let message = $state('');
  let node = $state<HTMLTextAreaElement | null>(null);
</script>
<label for="message">Message</label>
<Textarea id="message" name="message" bind:value={message} bind:ref={node} aria-describedby="message-help" required />
<p id="message-help">Write a message.</p>
```

`className` becomes Svelte `class` (including native class arrays/objects); React style objects become CSS strings. React refs become `bind:ref` and forwarded Svelte symbol attachments, with cleanup on removal. Native lowercase props replace React camel-case DOM props. React synthetic `onChange` fires during editing; Svelte `oninput` observes editing and native `onchange` observes the committed edit on blur. `bind:value` updates the caller's Svelte state and native form reset restores `defaultValue` (or empty when absent) and updates bound state; React controlled `value` retains current state on reset. Use `defaultValue` for an uncontrolled initial value/reset baseline. Framework-specific event/ref/binding assertions earn no React parity credit. Text content is supplied through `value`/`defaultValue`; React's deprecated textarea children initialization is outside this bounded slice.

The five [examples](../apps/docs/examples/base/TextareaExample.svelte) preserve the pinned placeholder, IDs, `rows=6`, invalid and disabled attributes, and description text. Native sections, headings, labels and a paragraph substitute for out-of-scope Example/Field components. The described example deliberately adds no `aria-describedby`: the pinned example supplies none explicitly, and full Field behavior/styling is not ported. The separate form fixture tests an explicit description association. The instruction “press enter to send” is retained source text; Textarea itself preserves native newline entry and implements no submit-on-Enter handler. This does not establish a shared upstream bug; a behavioral fix would require paired evidence and a deferred own-repository issue.

Nova is Tailwind input CSS. Use the [installation scaffold](installation.md)'s theme mappings and scan the current package output. For source copies from this checkout, copy `registry/bases/base/ui/textarea` plus `registry/bases/base/ui/dialog/classes.js`, provide `clsx` 2.1.1 and `tailwind-merge` 3.6.0, scan the copied directory, and copy the scoped Nova CSS with the [MIT notices](../packages/ui/THIRD_PARTY_NOTICES.md). The guide's historical fixed Dialog checkout predates Textarea; build archives from the current reviewed checkout. No Base upgrade is needed. Native disabled styles, invalid/focus rings, field-sizing content, minimum height, overrides and responsive `text-base`/`md:text-sm` remain source rules; a dark palette is not supplied or validated.

## Evidence and remaining gates

[Source hashes](../tests/reference/textarea-sources.json) identify the byte-exact wrapper, complete five-state example and scoped Nova CSS. The actual pinned wrapper executes in [DOM comparisons](../tests/dom/textarea.test.ts) and [paired browser probes](../tests/browser/textarea.spec.ts). No dedicated upstream Textarea test file was found during planning; these are source-derived/local comparison tests, not copied upstream test ports. The MIT [reference license](../tests/reference/LICENSE) and package notices cover the derived fixtures.

Test-first commit `0048bb0` failed the missing Nova section assertion and failed DOM suite resolution because the component did not exist. A further [actual-wrapper SSR comparison](../scripts/check-textarea-ssr.mjs) failed when spread defaultValue produced an empty server textarea and when HTML parsing stripped a leading newline. The wrapper now uses the defaultValue fallback only during SSR and forwards defaultValue explicitly on the native host, and compensates for the parser newline only when serializing the binding. These restore pinned behavior rather than introduce intentional differences. Independent review of `579a1e37b4cf79115fefb9f0c61a9ba94552ce5e` found initially undefined bound values crashed on a lazy bindable fallback; regressions also reproduced an undefined ref crash before correction. Both bindings now have no component fallback, so native defaultValue/binding initialization adopts a supplied draft without rejecting undefined caller state. These are local fidelity repairs restoring valid native initialization, not changes to pinned upstream behavior. Fresh consumers and hydration also probe these bindings. Hosted [run 36937969780](https://github.com/sveltery/ui/actions/runs/36937969780) passed 44/45 browser cases; the remaining desktop growth comparison measured a focus-color transition at unequal times. The new comparison waits for the existing transition to settle without changing any pinned style or expected result. The next hosted [run 36938696726](https://github.com/sveltery/ui/actions/runs/36938696726) passed all 45 main browser cases but exposed missing input/change handlers in the new fresh-consumer fixture; its assertions correctly observed zero callbacks. The fixture now supplies those consumer handlers, preserving the existing expectations and component behavior. The implemented DOM tests compare default/overridden classes, data-slot and native attributes to the actual pinned React wrapper, then exercise Svelte binding, input/change, FormData, ref identity, symbol attachments, defaultValue reset and cleanup. Browser probes cover light Nova computed styles at 1280/390px, focus/invalid/disabled/override and content growth, paired labels/forms/validation/newlines, plus Svelte SSR/hydration and pre-hydration edits. The [package check](../scripts/check-package.sh) checks root/subpath identity, declarations, SSR initial/default values and styles. [Fresh consumer checks](../scripts/check-installation.mjs) add Textarea to archive/source-copy SvelteKit consumers alongside unchanged Button and Dialog.
