# MessageScroller upstream test prerequisite

MessageScroller is a required entry in the pinned [Base registry wrapper](https://github.com/shadcn-ui/ui/blob/d75a96ab781f3d659be1ad287347d5887ce9f2fc/apps/v4/registry/bases/base/ui/message-scroller.tsx). It uses the `@shadcn/react/message-scroller` core, rather than `@base-ui/react`. A real Svelte primitive and styled wrapper remain unimplemented. This prerequisite exposes no component, public export or interactive behavior.

## Genuine geometry assertions

[The source ledger](../tests/reference/message-scroller-tests.json) identifies the immutable shadcn commit, Git blobs, SHA-256 hashes and exact byte lengths. The original geometry suite, geometry implementation, core types and shared render types are copied byte for byte with their [MIT notice](../tests/reference/shadcn-react/LICENSE). The [executed test adaptation](../tests/dom/message-scroller-geometry.test.ts) changes only the geometry import path; original fixtures, declaration names and expected results remain unchanged. [Provenance verification](../scripts/tests/message-scroller-provenance.test.mjs) enforces those boundaries.

The suite contains **17 ordinary declarations and 18 `expect` calls**. It checks padded start/center/end/nearest alignment, content bottom and spacer exclusion, first/last/unhandled anchor identity and scroll-edge thresholds. These assertions currently target the unchanged original DOM geometry implementation. Passing them supplies executed upstream-reference evidence and **zero Svelte implementation credit**. Moving the assertions to a real Svelte Base module, observing failures and repairing that implementation remains required.

The harness substitutes this project's Vitest 5.0.3 and jsdom 30.1.1 for upstream manifest ranges `^3.2.6` and `^28.1.0`. The upstream suite already stubs layout and computed padding because jsdom does not calculate browser geometry. That original fixture design remains intact; these cases establish no actual browser layout, native scrolling or wrapper CSS parity. React component types remain reference material; geometry execution does not exercise React component lifecycles.

## Headless architecture and remaining suites

The future `@sveltery/base/message-scroller` primitive must own Provider/context, stores and commands, the controller, native scroll intent, anchor/prepend preservation, ResizeObserver/IntersectionObserver/rAF lifecycle and cleanup, and SSR pending-scroll/hydration state. The UI wrapper may add the six pinned styled parts, actual local Button/configurable icons and framework API substitutions after that primitive is verified. UI controller/focus shims or placeholder interactive hosts supply no primitive coverage.

The same pin has 49 runtime declarations with 156 `expect` calls (including SSR/hydration), 17 browser declarations with 38 `expect` calls, and six performance declarations with nine `expect` calls. These are source counts, not executed results. All remain unported. React subscriber rerender-count, profiler and heavy-markdown performance expectations require explicit applicable Svelte equivalents or recorded omissions with zero ordinary credit; they must not be silently renamed or weakened. Meaningful geometry, scroll targets, asynchronous opening/restoration, appends/resize, intent, identity, visibility and prepend expectations must survive a future framework adaptation. Shared pinned defects require actual reproduction, a tracked issue and a separate correction decision.

Run `pnpm test -- tests/dom/message-scroller-geometry.test.ts` for these genuine reference assertions and `node --test scripts/tests/message-scroller-provenance.test.mjs` for immutable-source verification. Full local verification, fresh consumers, secured hosted browser regression gates and exact-head review are still required for the prerequisite's landing. No complete test port, behavioral acceptance, cross-version parity or production readiness follows from this scaffold.
