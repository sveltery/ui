## Behavior and dependency boundaries

Base retains immutable Base UI 1.8.0 behavior provenance at `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`. UI retains byte-exact shadcn `d75a96ab781f3d659be1ad287347d5887ce9f2fc` sources and React fixtures on `@base-ui/react` 1.6.0. The dependency upgrade supplies no new evidence equating those versions.

The pinned shadcn Input imports `@base-ui/react/input`, which delegates to Field.Control. Base's landed [standalone Input](https://github.com/sveltery/base/blob/d889e75bedfee9174c3b36d16fe8a9fb2d2a66d3/docs/input.md) supplies the real standalone primitive; contextual Field/Form registration, validation and message relationships remain deferred. UI's future styled Field composition is not an implementation of those Base contexts. Input inherits Base's existing [I-01 through I-04 compatibility entries](https://github.com/sveltery/base/blob/d889e75bedfee9174c3b36d16fe8a9fb2d2a66d3/docs/upstream-differences.md): framework substitutions, user-directed native Svelte reset defaults, accepted next-tick controlled restoration and the narrow unsupported imperative reset-handler reassociation plus stopped-propagation combination. The latter remains characterized by unchanged negative assertions with four explicitly expected failures and zero ordinary Input/Field credit. This upgrade makes no new behavior acceptance decision.

The pinned shadcn Field imports styled Separator, whose wrapper imports the actual Base Separator primitive. Landed [Base Separator](https://github.com/sveltery/base/blob/d889e75bedfee9174c3b36d16fe8a9fb2d2a66d3/docs/separator.md) is available, but UI has no styled Separator export yet. Actual React 1.6.0 and Base 1.8 both emit `data-orientation="horizontal"`/`"vertical"`; the pinned shadcn wrapper CSS instead selects `data-horizontal`/`data-vertical`. Direct React SSR confirms the unmatched selectors are shared with the pin, rather than introduced by this dependency update. Future styled Separator must preserve this questioned behavior, retain the actual reference reproduction and characterize computed effects before any separate accepted correction. The source/actual SSR mismatch is tracked in [issue #27](https://github.com/sveltery/ui/issues/27); computed styled-browser effects and a separate correction remain unverified. No such wrapper is added here.
