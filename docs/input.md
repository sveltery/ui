# Native Input draft

The proposed `Input` is a real Base-backed adaptation of pinned shadcn `d75a96ab781f3d659be1ad287347d5887ce9f2fc`; it is **merge blocked** by the native checked-state prerequisite in locked Base. It is not a landed or ready component. Declared native checkbox/radio behavior remains failing rather than silently excluded.

The [source manifest](../tests/reference/input-sources.json) retains exact wrapper, complete ten-function examples and Nova Input section (677–680) bytes and hashes. The implementation uses actual locked Base Input, keeps the pinned class string, caller data/native attribute precedence and merged caller classes, and adds the exact Nova rule to the existing component layer. Type omission stays omitted; the native browser default applies. Input provides no contextual Base Field/Form implementation.

## Native Svelte API and substitutions

The draft exports `Input` at the root and `@sveltery/ui/input`, plus a local `InputProps` type convenience. Native input attributes become Svelte native input attributes and events; static `className` becomes static Svelte class strings, arrays or dictionaries; object CSS becomes CSS strings; React refs become a fallback-free bindable `HTMLInputElement` ref and enumerable symbol attachments. Native Svelte nullable style/disabled values pass unchanged to the actual primitive host through a localized internal type assertion because Base's declarations omit null. This does not manufacture behavior. The ref narrowing is valid only because the wrapper always uses the primitive's native input host and does not expose its custom render API.

React edit `onChange` translates to native Svelte `oninput`; Svelte `onchange` remains the native commit event. Controlled owners pass `value` explicitly and update it in native event handlers. No wrapper `bind:value`, Base `onValueChange`, state-dependent class callback, custom render, variant or invented Field/Form state is advertised. Static class dictionaries use unknown values to prevent clsx's any-valued dictionary from structurally advertising function callbacks; normalization always uses static clsx before class merging. A caller can use undefined/null refs without a non-null bind fallback.

Standalone Base's already recorded value reset/restoration limitations I-02/I-03/I-04 remain inherited: native reset defaults, next-tick restoration and the narrow unsupported stopped imperative reset-handler form reassociation case. The newly discovered checked-state failures are not accepted under those historical decisions. Generated identifier bytes differ across frameworks; paired tests normalize only generated ID bytes while checking explicit IDs. These framework API/named-type substitutions are proposed implementation; no new specific acceptance or complete cross-version parity is inferred.

They remain in default verification without expected-failure markers. The other ten cover native props/classes, static nullable forwarding, native events, explicit owner accept/reject/rewrite, native hosts/refs, symbol attachments and replacement/cleanup, form association and already recorded value-reset behavior. Public type checks exercise native props and reject added callback/render/variant/style-object APIs. None of these local supplements earns copied upstream ordinary-test credit.
