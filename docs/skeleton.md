# Experimental native Skeleton

A bounded native Svelte 5 `div` port of [the pinned shadcn Skeleton wrapper](https://github.com/shadcn-ui/ui/blob/d75a96ab781f3d659be1ad287347d5887ce9f2fc/apps/v4/registry/bases/base/ui/skeleton.tsx), at `d75a96ab781f3d659be1ad287347d5887ce9f2fc`. It requires no Base primitive. The package remains private and unpublished; selected contracts do not establish full shadcn parity or production readiness.

Import `Skeleton` from `@sveltery/ui` or `@sveltery/ui/skeleton`. The single [registry component](../apps/docs/registry/bases/base/ui/skeleton/Skeleton.svelte) supplies the exact pinned `cn-skeleton animate-pulse` classes and [Nova section](../tests/reference/skeleton-nova.css), lines 1222–1225. The native `div` forwards attributes, styles, events and symbol attachments. A caller can override `data-slot="skeleton"`, merge classes with the existing `cn` equivalent, and provide children. The component does not supply dimensions: examples set them through caller classes.

```svelte
<script lang="ts">
  import { Skeleton } from '@sveltery/ui/skeleton';
  let node = $state<HTMLDivElement | null | undefined>();
</script>
<Skeleton class="h-4 w-40" bind:ref={node} />
```

React `className` becomes Svelte `class`, including arrays and objects; React style objects become native CSS strings. React refs become `bind:ref` and Svelte attachments. `ref = $bindable()` permits initially undefined caller state, adopts the actual host and clears to null on removal. React children become a Svelte snippet. Native event names replace React synthetic event names. These framework API substitutions earn no React API parity credit; the [compatibility register](upstream-differences.md) records their decision status separately from source fidelity.

Skeleton adds no role, live region, `aria-busy`, keyboard handling, focus behavior or loading-state controller. A consumer supplies any semantic loading announcement and controls its lifetime. The pinned source applies `animate-pulse` unconditionally, including when the browser prefers reduced motion; this port preserves that rule. A caller can use `animate-none`. No behavior correction is introduced here.

The [gallery](../apps/docs/examples/base/SkeletonExample.svelte) includes supplemental Basic and Override probes and the pinned Avatar, Text, Form and Table shapes. Form and Table contain placeholder `div`s, without real fields or table semantics. The original example's Card composition remains deferred until Card itself is ported; it is not approximated. Native sections/headings replace the out-of-scope Example/ExampleWrapper layout. The Table's three identical source rows use a keyed Svelte loop. That syntax change preserves this static shape and does not add dynamic table behavior. These examples establish selected shapes inside a shared substituted harness, not full Example or Card visual/API parity.

For source copies, copy `registry/bases/base/ui/skeleton` and `registry/bases/base/ui/shared/classes.js`, retain `clsx` 2.1.1 and `tailwind-merge` 3.6.0, scan both copied sibling directories, and copy Nova CSS with the [MIT notices](../packages/ui/THIRD_PARTY_NOTICES.md). Use the [installation guide](installation.md)'s Tailwind theme mappings and exact reviewed checkout for both archives and source copies. Skeleton's CSS uses the consumer's `muted` background and radius mappings; no new theme or dark palette is supplied.

## Evidence and remaining gates

[Immutable source hashes](../tests/reference/skeleton-sources.json) cover the byte-exact wrapper, complete original example, scoped Nova section and shared pinned MIT [license](../tests/reference/LICENSE). The manifest also records the full upstream Nova file hash before extraction. The [selected reference example functions](../tests/reference/skeleton-selected-examples.tsx) retain the actual Avatar/Text/Form/Table bodies unchanged, replacing their imports and Example layout only. A provenance assertion checks every selected function body against the byte-exact full example; [the React gallery](../tests/reference/SkeletonGallery.tsx) executes those functions and the actual pinned wrapper. Basic and Override are explicitly local supplemental probes. No dedicated upstream Skeleton test was identified; these tests are source-derived local comparisons, not copied upstream tests.

Test-first commit `bf531c5` failed suite resolution because the component did not exist. The [DOM comparisons](../tests/dom/skeleton.test.ts) check exact native host/attributes/classes against that actual wrapper, class conflicts, unchanged selected example shapes, initially undefined refs, reactive declaration tags, native callbacks, stable host identity during updates, attachment cleanup and reattachment. The [browser comparisons](../tests/browser/skeleton.spec.ts) compare geometry and computed Nova/animation rules at 1280px and 390px against actual selected React examples. They also check the preserved reduced-motion behavior, SSR host reuse through hydration, reactive children/title updates and matching ref/attachment cleanup. Animation phase opacity is deliberately not treated as deterministic between separately loaded pages; the underlying pulse rule is compared directly.

At the implementation checkpoint, all six focused DOM cases and focused lint passed. Empty/absent children match the actual wrapper; the snippet probe matches its text child. The integrator also supplies actual paired React/Svelte SSR and distribution gates. Final-head lint, types, runtime tests, SSR/client builds, archive/public declarations, fresh archive/source-copy consumers, secured hosted Chromium with zero retries, independent review and configured automatic review remain required. Local or historical results cannot certify later changes, and a ready transition requires waiting for the newly triggered automatic review. Broader Card/Example composition, dark palettes, Firefox/WebKit and assistive-technology behavior remain unclaimed. See [readiness gates](readiness.md) and the [compatibility register](upstream-differences.md).
