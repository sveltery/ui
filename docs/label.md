# Experimental native Label

This bounded Svelte 5 slice follows [shadcn's native Label at `d75a96ab781f3d659be1ad287347d5887ce9f2fc`](https://github.com/shadcn-ui/ui/blob/d75a96ab781f3d659be1ad287347d5887ce9f2fc/apps/v4/registry/bases/base/ui/label.tsx) and Nova lines 788–795. Import the single `Label` export from `@sveltery/ui/label` or the root. The [registry implementation](../apps/docs/registry/bases/base/ui/label/index.ts) renders a native `label`; it introduces no Base primitive, disabled state, custom host, variant or render API. The package remains private and unpublished, and whole-library parity and production readiness remain blocked.

```svelte
<script lang="ts">
  import { Label } from '@sveltery/ui/label';
  import { Textarea } from '@sveltery/ui/textarea';
  let label = $state<HTMLLabelElement | null>();
</script>
<Label for="message" bind:ref={label}>Message</Label>
<Textarea id="message" placeholder="Message" />
```

Native association is consumer-supplied through matching `for` and control `id`, or a nested labelable control. Activation/focus follows the browser; the wrapper supplies no focus handler. `htmlFor` becomes Svelte `for`, `className` becomes `class`, React object styles become CSS strings, children become snippets, React refs become `bind:ref` or symbol attachments, and synthetic events become native handlers such as `onclick`. Native label attributes/events remain reactive, and caller attributes can override or omit `data-slot`. Caller classes merge after the pinned tokens with pinned `cn` 0.2.2. Refs may start undefined or null, receive the actual `HTMLLabelElement` after attachment, and clear to null on removal; forwarded attachment cleanup runs on replacement/removal. These framework probes earn no React parity credit. See current Svelte documentation for [$props](https://svelte.dev/docs/svelte/$props), [bindings](https://svelte.dev/docs/svelte/bind) and [attachment forwarding](https://svelte.dev/docs/svelte/@attach).

The exact wrapper tokens are `cn-label flex items-center select-none group-data-[disabled=true]:pointer-events-none peer-disabled:cursor-not-allowed`. The [scoped Nova CSS](../tests/reference/label-nova.css) adds gap, font and line height plus `group-data-[disabled=true]:opacity-50` and `peer-disabled:opacity-50`. Group matching requires an ancestor with `group` and `data-disabled="true"`; a preceding native disabled `peer` controls the peer selector. The separate `.cn-label-aria` rule uses the genuine `shadcn/tailwind.css` disabled variant: it matches a preceding `peer` with `data-disabled="true"` or a present value other than `"false"`, including empty presence. Explicit `data-disabled="false"` is excluded and retains opacity `1`. The wrapper does not add that class. These are styling selectors, not a Label disabled API. A disabled associated control retains native disabled behavior. Positive and negative selector witnesses in the [browser fixtures](../tests/browser/label.spec.ts) are supplemental source-derived probes using native controls, not ported Input/Checkbox compositions.

Only **With Textarea** is selected from the [complete pinned examples](../tests/reference/label-example.tsx). The [Svelte example](../apps/docs/examples/base/LabelExample.svelte) and [React gallery](../tests/reference/LabelGallery.tsx) replace Example/ExampleWrapper with native sections/headings and Field with a plain div. The actual Label and Textarea wrappers retain `label-demo-message`, the Message label and placeholder. Field/Example layout, behavior and APIs are unimplemented; this is an explicitly bounded scaffold adaptation, not full example/gallery parity. With Checkbox, With Input and Disabled remain deferred because their styled controls are missing.
