# Security reporting

Sveltery UI currently contains documentation only and has no supported production release or promised response time. Report non-sensitive documentation bugs through [issues](https://github.com/sveltery/ui/issues).

For suspected vulnerabilities, avoid publishing exploit details, secrets or private data in public issues. If the repository's Security tab offers **Report a vulnerability**, use that private channel. Its availability depends on repository settings. Otherwise open a public issue requesting a private contact channel without sensitive details, and wait for a maintainer to establish one. No dedicated security email address is configured.

Include the affected commit, minimal reproduction and impact. Route upstream-specific vulnerabilities through the upstream project's own security process.
